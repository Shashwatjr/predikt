# Completion recovery — 2026-10-27

Local disposable Postgres only. No production, Neon, DNS, push, or deployment.

## Defect

`end` stored `prediction_rooms.status=completed` before `result_ready` fanout. `reachMilestone` stored `room_milestones.status=reached` before later prediction rank, Clout, Aura, and reward-ledger writes. The next creator call then stopped at `Room is already completed` or `Milestone already reached`, so committed credits and the first recipient stayed in place while missing scores and notifications never ran. `lockedStatus` is not a score claim: predictions are locked before scoring. Pre-fix output: `recovery-before.json`.

## Fix

The creator can resume a completed room through `end` and the arrival entry points. Resume scores only predictions whose `rankForMilestone` is still null, under a per-prediction transaction lock, using the stored arrival time or stored option. It then calls the existing `finalizeRoom` path. Completion columns are not rewritten. A cancelled room still rejects. A fully scored live milestone still rejects a second reach. Same-key reward grants take a transaction advisory lock before the ledger insert so a concurrent grant waits instead of aborting the outer transaction. Scoring amounts, eligibility, and creator-only authority are unchanged.

## Result

`backend/scripts/verify-finalization-external.ts` on loopback `predikt_ui`: partial score then reach and end; notification fanout to three recipients then retry; a second connection retry that does not change outcome timestamps or balances; simultaneous reach and end; eight finalizations across two connections (8 fulfilled); cancelled room writes nothing. Assertions covered ranks, Aura/Clout/Gem/credit balances, ledger row counts, and one finalization claim. Output: `recovery-after.json`.
